# safe-change

Use this skill when implementing a feature, bug fix or refactor.

Rules:
1. Explain the intended change before editing.
2. Prefer the smallest viable change.
3. Preserve current behavior unless explicitly requested.
4. Avoid unrelated formatting, renames or dependency changes.
5. After editing, list modified files and validation steps.
6. If tests exist, run the most relevant tests.

If design skills are active:
- preserve existing design language
- avoid aesthetic-only modifications
- prioritize usability over novelty
